# 판매 분석 입력·출력 명세

이 문서는 교육용 합성 판매 데이터의 판정 기준입니다. 실제 기업의 회계 정책을 뜻하지 않습니다. 모든 금액은 원 단위 정수이며 세금·환율 계산은 하지 않습니다.

## 1. 읽기

- UTF-8 또는 UTF-8 BOM을 사용합니다. LF와 CRLF 모두 허용합니다.
- 쉼표 구분 CSV입니다. CSV 파서로 읽습니다. 문자열을 쉼표나 줄바꿈으로 직접 나누지 않습니다.
- 필수 열 집합은 date, order_id, category, product, quantity, unit_price, region입니다.
- 열 순서는 달라도 됩니다. 빠진 열·추가 열·중복 헤더는 오류입니다.
- 헤더 뒤 데이터가 0건이면 NO_DATA입니다. 빈 파일이나 없는 경로 역시 정상 결과로 처리하지 않습니다.
- 오류 위치는 헤더를 1번으로 세는 **CSV 레코드 번호**입니다. 셀 안 줄바꿈 때문에 물리적인 텍스트 줄 번호와 다를 수 있습니다. 파일 전체에 대한 NO_DATA의 번호는 0입니다.

## 2. 값 검사

| 열 | 규칙 |
|---|---|
| date | 정확한 YYYY-MM-DD 형식의 실제 날짜 |
| order_id | 비어 있지 않은 문자열, 파일 안에서 중복 금지 |
| category·product | 아래 카탈로그의 정확한 표기와 관계 |
| quantity·unit_price | 선택적 부호 다음 ASCII 숫자로만 구성된 정수이며 값은 1 이상. 공백·소수점·천 단위 쉼표 불허 |
| region | Busan, Daegu, Daejeon, Gwangju, Incheon, Jeju, Seoul, Ulsan 중 하나 |

| category | product |
|---|---|
| Office | Keyboard, Mouse, Mechanical Keyboard, Desk Lamp |
| Monitor | 24-inch Monitor, 27-inch Monitor, 32-inch Monitor |
| Accessory | USB-C Hub, Webcam, Laptop Stand, Noise-Canceling Headset |
| Storage | Portable SSD 1TB, USB Drive 128GB |

수량·단가에는 별도 상한을 두지 않습니다. 설명용 소액 단가, 할인 단가, 큰 주문도 입력 계약을 만족하면 유효합니다. 제품별 고정 단가라고 가정하지 않습니다. 공백 제거·대소문자 변환·오류 행 제외를 통해 입력을 몰래 보정하지 않습니다.

## 3. 계산과 출력

1. 모든 입력을 검사합니다.
2. 행 매출 = quantity × unit_price입니다. 총매출, 카테고리 매출, 제품 매출, 총수량을 계산합니다.
3. 제품 순위는 매출 내림차순, 동률이면 제품명 Unicode 오름차순입니다. 3개 미만이면 존재하는 제품만 출력합니다.
4. summary.csv와 report.md를 요청에서 지정한 결과 폴더에 저장합니다. 보고서는 총매출·카테고리 집계·상위 3개를 구분합니다.
5. summary.csv의 정확한 열은 `section,name,value`입니다. `section`은 total,category,product_top3를 사용합니다. total의 name은 revenue와 units입니다. 금액·수량 value는 구분기호 없는 정수입니다. 카테고리는 이름 오름차순, 제품은 위 순위대로 씁니다. total 두 행은 revenue,units 순서입니다.
6. 동일 논리 입력의 출력 바이트는 같아야 합니다. 현재 시각·임시 경로·입력 파일명은 결과에 넣지 않고 실행 로그에 둡니다.

## 4. 실패와 보존

- 정상 실행은 종료코드 0입니다. 입력 계약 오류는 코드 2입니다.
- 기본 정책은 첫 오류 보고입니다. 행 순서로 검사하고 같은 행은 헤더에 적힌 순서가 아닌 위의 표 순서로 검사합니다. 헤더 오류가 행 오류보다 우선합니다. 중복 헤더를 먼저 검사합니다.
- stderr에 CSV 레코드 번호, 필드, 이유 또는 오류 코드를 남깁니다.
- 정상 출력은 모든 입력 검사를 마친 뒤에만 생성·교체합니다. 오류 입력에서는 기존 두 결과 파일의 바이트가 그대로여야 합니다.
- 전체 오류 수집은 선택 확장입니다. 비교 실행 A/B에서는 같은 정책을 유지합니다. 혼합 오류 파일에서 첫 오류만 나오는 것이 기본 정책의 정상 결과입니다.

## 5. 관계 검사

relations/base.csv를 기준으로 reordered.csv, utf8_bom.csv, windows_crlf.csv, reordered_columns.csv의 논리 결과와 출력은 같아야 합니다. 원본 파일의 해시는 서로 다를 수 있습니다.

double_price.csv는 단가만 두 배입니다. 금액 집계는 두 배, 수량과 순위는 같아야 합니다. part_a.csv와 part_b.csv의 전체 집계를 더하면 base 집계가 됩니다. 각 부분의 상위 3개만 더해 전체 상위 3개를 구할 수 있다고 가정하지 않습니다.

## 6. 실행 인터페이스와 적용 시점

6교시 이후 프로그램의 공통 실행 인터페이스는 `python analyze_sales.py --input 입력경로 --output-dir 결과폴더`입니다. 상대 경로는 실행 위치 기준으로 해석합니다. 원본 입력은 변경하지 않습니다. 실행 위치·명령·종료 코드·실제 출력 파일을 기록합니다.

이 명세는 제공된 이후의 실습에 적용합니다. 3교시 최초 응답에서 이 출력 형식이나 오류 처리 정책이 없었다는 이유만으로 오답 처리하지 않습니다. 주어진 입력으로 계산한 수치가 틀린 경우와 아직 주지 않은 업무 요구는 구분합니다.

입력 파일의 행마다 필드 수는 헤더 수와 같아야 합니다. 원 단위 정수 계산을 사용합니다. 날짜는 교육 시나리오이므로 오늘 이후라는 이유만으로 제외하지 않습니다.

출력 바이트 동일성은 같은 프로그램·환경에 동일 논리 입력을 주었을 때 확인합니다. 서로 다른 모델이 작성한 프로그램끼리는 명세 충족과 수치를 비교하며 문장까지 동일할 필요는 없습니다.

같은 행의 검사 순서는 date → order_id → category → product → quantity → unit_price → region입니다. category 검사에서는 알려진 제품과의 분류 관계도 확인합니다. 존재하지 않는 입력 경로는 INPUT_NOT_FOUND, 빈 파일·헤더만 있는 파일은 NO_DATA로 기록합니다. 둘 다 종료 코드 2이며 기존 출력은 보존합니다. 헤더의 누락·추가 열은 HEADER_MISMATCH입니다.
